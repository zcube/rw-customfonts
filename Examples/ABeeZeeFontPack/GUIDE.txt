Custom Fonts - ABeeZee Example
==============================

A ready-to-install, font-only mod for RimWorld 1.4–1.7.
It uses About.xml and font files, with no DLL, C# project or Defs required.
The metadata and guide use the repository's MIT license. The fonts use the
SIL Open Font License 1.1 provided in Fonts/OFL.txt.

Installation
------------
1. Download this repository. If you cloned it with Git, run from its root:

   git lfs pull --include="Examples/ABeeZeeFontPack/Fonts/*.ttf"

   Check that the TTF files are approximately 46–47 KB each. A roughly 130-byte
   Git LFS pointer is not a usable font file.

2. Copy the entire Examples/ABeeZeeFontPack directory into the game's Mods folder.
   Example: Mods/rw-customfonts-abeezee-example/About/About.xml
   On macOS 1.4–1.6, use RimWorldMac.app/Mods; on 1.7, use Mods in the game root.
   Copy the example directory itself, rather than this repository's root.

3. Install a Custom Fonts build from this repository that supports expansion mods.
   Enable mods in this order, then restart the game:

   Harmony → Core and any DLC you use → Custom Fonts - Forked →
   Custom Fonts - ABeeZee Example

4. Open Mod settings → Custom Fonts and select either entry:

   (Bundled) ABeeZee (Regular) [Custom Fonts - ABeeZee Example]
   (Bundled) ABeeZee (Italic) [Custom Fonts - ABeeZee Example]

   Both entries are available for UI fonts, world fonts and each target's fallback
   list. Search matches both the font name and the providing mod's name.
   No OS font installation or manual search path is required.
   ABeeZee is a Latin-script example. For Korean text, select a primary or fallback
   font that supports Hangul.

Creating your own font pack
---------------------------
1. Copy this directory.
2. Update name, author, description and packageId in About/About.xml with your own
   values and a unique packageId. Keep the zcubekr.customfonts dependency and
   loadAfter entry.
3. Replace the example fonts in Fonts with fonts that permit redistribution,
   including their original copyright notices and licenses. Update provenance.json
   with the actual files' official sources and hashes. Do not reuse the example's
   font license for unrelated fonts.
4. Supported formats are .ttf, .otf and .ttc. Subdirectories are scanned recursively.
   TTC collections use the first face. Names and styles come from OpenType metadata.
5. Version-specific Fonts directories and LoadFolders.xml are supported. A higher-
   priority content root overrides the same relative font path. Duplicate faces
   within one pack use the first entry by content-root priority, then sorted file
   path. Faces from different packs remain separate entries.
6. Saved selections use packageId and face name. Keep both stable after publishing.
   Changing the displayed mod name does not invalidate saved selections.
7. Restart after changing active mods. During development, if only font files have
   changed, use Refresh font list / apply search options in the etc tab to refresh
   the bundle catalog and reload fonts.

Automated tests
---------------
From the repository root, run:

  task test

This checks the actual example's dependency/load-order XML, font-only contents,
fixed hashes and license notices, registration of both styles, Unity primary and
fallback import bytes, and file-cache reuse. These checks do not launch the game
and therefore do not establish that native rendering works.

Live-game integration tests require Python 3, a graphical desktop, Harmony and an
installed game. Close other RimWorld instances, then build and install the matching
Custom Fonts version before running:

  task build
  task export
  task test_font_pack_game

For another installation, for example:

  task export STEAM_APPS="/path/to/1.6/steamapps"
  task test_font_pack_game VERSION=1.6 STEAM_APPS="/path/to/1.6/steamapps"

Harmony must also be discoverable in that installation's Mods or Workshop paths.
Harmony 2.4 introduced native Apple Silicon ARM64 patching support:
https://github.com/pardeike/Harmony/releases/tag/v2.4.0.0
On Apple Silicon, update Harmony to 2.4 or newer and use the default native mode.
This example also passed native integration tests with Harmony 2.4.3.
When deliberately testing a legacy Harmony 2.3.x setup, you can select x86_64
execution through an existing Rosetta installation:

  task test_font_pack_game VERSION=1.6 MAC_ARCH=x86_64 STEAM_APPS="/path/to/1.6/steamapps"

For the direct runner, use --mac-arch x86_64. It does not install Rosetta.
To run without Task:

  python3 Tests/run_font_pack_integration.py --game-root "/path/to/RimWorld" --version 1.7

The runner temporarily installs the example into the game's Mods directory and
registers it through actual ModsConfig.xml files. It refuses to overwrite an
existing example installation and removes its temporary installation when finished.
It uses temporary savedatafolder profiles and leaves your ordinary profile intact.
The active and restart scenarios share a test profile; wrong-order and disabled
scenarios use separate profiles. Only the test game process is terminated afterward.

Checks include:
- Actual active-mod order, registration of both bundled styles, and recognition
  of a font-only mod as loaded content.
- Mod-name labels, discovery independent of OS/manual-path/recursion options,
  and lazy loading before selection.
- Native Regular/Italic glyph rasterization in Tiny, Small and Medium UI fonts.
- TMP glyph geometry and selected-font bindings on visible live world labels.
- Original pack fallback bytes for all four targets, refresh, and persistence
  of primary/fallback selections across restart.
- Exclusion of packs before Custom Fonts and packs that are disabled.

The printed Evidence directory contains per-scenario results, stdout, test profiles
and results.json. Use --output to select an empty evidence directory. Do not run the
live-game checks in CI without a graphical desktop. Recorded results and limits are
in Docs/FontPackVerification.txt in the repository.
